# TestRail AI Generator для Codex, Gemini и Copilot

Локальный сервер связывает расширение Chrome TestRail AI Generator с Codex, Gemini CLI и GitHub Copilot. Чат может читать кейсы и промпты и редактировать черновики. Панель Chrome может запускать генерацию кейсов, спецификаций и автотестов через CLI выбранного агента.

## Установка через консольное меню

Скачайте [`testrail-chat-setup.zip`](https://github.com/mikhailhimei/TestRail-AI-Generator-MCP/releases/latest/download/testrail-chat-setup.zip), распакуйте его и откройте папку `testrail-chat`. Запустите `Install Windows.cmd` в Windows, `Install macOS.command` в macOS или `sh "Install Linux.sh"` в Linux. Меню также можно открыть командой `node setup.mjs`. Требуется Node.js 22.12 или новее.

Введите **1** для Codex, **2** для Gemini CLI, **3** для GitHub Copilot, **4** для Qwen и DeepSeek или **0** для выхода. Для Codex установщик установит плагин. Для Gemini и Copilot он проверит или установит выбранный CLI, скопирует сервер в папку данных пользователя и зарегистрирует его в настройках клиента. Пункт Copilot настраивает общий пользовательский MCP для Copilot CLI и актуального чата Copilot в VS Code. Откройте новую сессию, войдите в аккаунт при необходимости и подтвердите подключение в панели Chrome. Расширение Chrome устанавливается отдельно. Инструкция доступна в [репозитории расширения](https://github.com/mikhailhimei/TestRail-AI-Generator).

## Установка для Codex

В едином установщике выберите **1. Codex**. Он использует установленный Codex CLI или скачивает его из npm. В Linux для окна подтверждения нужны графический сеанс и пакет `zenity`, а в macOS используется штатный `osascript`.

После установки:

1. Создайте **новый чат Codex** с плагином **TestRail AI Generator**. Продолжение старой беседы может не загрузить только что установленный плагин.
2. Откройте панель расширения. В настройках выберите **Codex (локальный сервер)** и нажмите **Подключить Codex**.
3. Разрешите подключение в появившемся окне. В Windows нажмите **Да**.

Установщик сразу запускает сервер в отдельном фоновом процессе и настраивает запуск при входе в систему. Для генерации из расширения открывать проект, консоль или чат не требуется. Для команд из чата нужна открытая панель Chrome. Закрытие чата не останавливает сервер. При необходимости один раз выполните вход в Codex: `codex login`.

В чате можно попросить получить промпт BFF, создать тест-кейсы или подготовить спеку. Изменения сохраняются в черновиках расширения, без автоматической публикации в TestRail или Confluence. Подробности — [инструкция плагина](testrail-chat/README.md).

## Подключение Gemini CLI и GitHub Copilot

В едином установщике выберите **2. Gemini CLI** или **3. GitHub Copilot**. Откройте новую сессию выбранного клиента и войдите в аккаунт.

- **Панель Chrome.** Выберите **Gemini MCP** или **Copilot MCP**, нажмите «Подключить» и подтвердите доступ. Для команд из чата оставьте панель открытой; для генерации из расширения MCP-чат не нужен. Закройте старые сессии с сервером предыдущей версии, чтобы новый сервер мог занять локальный порт.

Для генерации из Chrome нужен авторизованный `gemini` или `copilot` в PATH процесса MCP. Для доступа к MCP из чата Copilot достаточно расширения VS Code. Для генерации АТ укажите корень Git-проекта и настройте в CLI разрешения на нужные команды проверок и браузерные инструменты. Gemini CLI должен доверять папке проекта.

## Подключение Qwen и DeepSeek из чата

В общем установщике выберите **4. Qwen / DeepSeek (Qwen Code)**. Установщик проверит или установит Qwen Code, скопирует локальный сервер и зарегистрирует `testrail-extension` в пользовательских настройках Qwen Code. Сервер запускается при подключении чата к MCP.

1. Откройте новый чат командой `qwen`. Настройте Qwen или DeepSeek в Qwen Code по [инструкции по провайдерам моделей](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/). Ключ модели задаётся в Qwen Code.
2. Проверьте подключение сервера командой `/mcp list`.
3. В расширении Chrome выберите **Codex (локальный сервер)**, нажмите **Подключить Codex** и подтвердите доступ. Через это подключение чат Qwen Code сможет работать с черновиками TestRail. Кнопки генерации из самой панели по-прежнему используют агента, выбранного в панели.

## Как показывается прогресс

Установщики для Windows, macOS и Linux проверяют `--version`. При отсутствии CLI нужен `curl` и npm из комплекта Node.js. Установщик показывает прогресс скачивания каждого основного npm-архива. Для архива с известным размером отображается процент. Распаковка и установка npm идут отдельным этапом, на котором npm может скачать дополнительные зависимости. Если VS Code или Codex был открыт, перезапустите его после установки CLI.

## Исходники

Для чтения локального проекта включите «Разрешить чтение исходников на сервере» в панели Chrome. Сервер проверяет Windows-, UNC- и Linux-пути до запуска CLI; пути с пробелами заключайте в кавычки. В Codex на Windows используется нативная песочница `elevated` с файловым режимом `read-only`. Если песочница ещё не настроена, выполните [настройку Codex для Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). После обновления любого MCP-архива переподключите сервер, чтобы загрузить исправленный runtime.

Для клонирования исходников с Windows CLI нужен Git LFS:

```sh
git lfs install
git clone https://github.com/mikhailhimei/TestRail-AI-Generator-Cursor.git
cd TestRail-AI-Generator-Cursor
git lfs pull
```

Обычный GitHub Source code ZIP может содержать LFS-указатели вместо исполняемых файлов. Для установки используйте единый установщик из релиза.

## Данные и проверка

Ключ подключения создаётся локально; пользовательские токены и вход Codex в пакет не включаются. Обновление плагина сохраняет подключение. Сервер слушает только `127.0.0.1` и запрашивает подтверждение перед передачей ключа расширению.

Установщики проверены в POSIX shell с имитацией системных зависимостей; ZIP проверен на права выполнения и окончания строк LF. Проверка на реальных macOS/Linux пока не выполнена.


## JSON-моки из чата через MCP (v1.5.0)

Для новых ТК `add_test_cases` принимает `jsonMocks: [{"name":"claims-list.json","json":"{\"items\":[]}"}]`. Для существующих ТК сначала прочитайте `get_extension_state`, затем вызовите `upsert_case_mocks` с актуальными `sessionId`, `expectedRevision`, `caseId` и `mocks` (имя `.json` и содержимое JSON строкой). Инструмент создаёт/обновляет файлы по имени, сохраняя остальные моки и поля ТК. Повторное создание самих ТК не требуется. После записи перечитайте состояние и проверьте массив `jsonMocks`. JSON в предусловиях не является файлом и не заменяет этот инструмент.

Нужна актуальная версия приложения/расширения с разделом «Моки». Команды MCP работают одинаково для Codex, Gemini CLI, Copilot и других совместимых MCP-клиентов. Они сохраняют только черновики; вложения отправляются в TestRail при отдельной отправке ТК из приложения. После обновления перезапустите MCP и откройте новый чат, чтобы загрузить новые схемы и инструкции.


Релиз содержит `testrail-chat-setup.zip` и `SHA256SUMS.txt`. Для сборки установщика используйте `python3 installers/package.py <output-dir> --setup-only`.

## Фоновый сервер

После установки сервер работает без открытого проекта и консоли. Если MCP-клиент обнаружит, что сервер остановлен, он запустит отдельный фоновый процесс. Закрытие клиента его не останавливает.

При обновлении закройте старые MCP-подключения и один раз запустите новый установщик. Автозапуск: Windows — файл `TestRail AI Generator.vbs` в пользовательской папке Startup; macOS — `~/Library/LaunchAgents/com.testrail-ai-generator.bridge.plist`; Linux — `~/.config/autostart/testrail-ai-generator.desktop`. Диагностика запуска через MCP записывается в `.codex-bridge/server.log` рядом с токеном.
